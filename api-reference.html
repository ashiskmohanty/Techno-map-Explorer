How the APIs are used

The browser performs deterministic ranking over the loaded repository. Flask provides data, persistence, SAP access and administrative operations. The LLM is optional and limited to intent interpretation.

Explore knowledge

Load the repository, rank objects locally, optionally refine intent with an LLM, then enrich results with live SAP evidence.

Trace impact

Combine local planning links with SAP incoming, outgoing and method-level dependencies to map change impact.

Maintain knowledge

Refresh source data, add or edit objects, retain verified teachings, capture feedback and review usage metrics.

Data Layer

This application does not use SQL, NoSQL, or a separate database server. Its data layer is a collection of JSON, JSONL, JavaScript and Excel files read by Flask from the application filesystem.

Database typeFile-backed local persistence. JSON holds structured state, JSONL holds append-only events, and Excel provides rebuild inputs and exports.
Default locationThe same directory as app.py. In this workspace that is the PS - Process Explorer project folder.
Runtime accessThe browser calls Flask APIs. Flask reads, merges and writes files; the browser normally does not modify storage files directly.
Current application root:
C:\MS - Surface\Agent in VScode -1\PS - Process Explorer
In a container or another deployment, the default location moves with app.py. Environment variables can redirect several writable stores to shared or durable storage.

Repository fetch and merge flow

The API returns a composed in-memory view; overlays do not directly rewrite the generated base repository during reads.

flowchart LR
  UI[Browser boot] -->|GET /api/data; no-store| API[Flask API]
  API --> LOAD[load_or_build]
  LOAD --> BASE[(data.json)]
  BASE --> MERGE[In-memory merge]
  MAN[(manual_objects.json)] --> MERGE
  EDIT[(object_edits.json)] --> MERGE
  PLAN[(RSPLS and planning JSON)] --> MERGE
  FOX[(FOX formulas JSON)] --> MERGE
  MERGE --> RESP[JSON response]
  RESP --> STATE[Browser State and local ranking]
  API -. fallback if missing .-> BUILD[build_data.py]
  BUILD --> BASE

Write and analytics flow

Mutable JSON stores use a best-effort lock and atomic replacement. Event logs append one JSON record per line.

flowchart TB
  WRITE[Teaching, feedback, manual or edit API] --> LOCK[Acquire file lock]
  LOCK --> READ[Read current JSON]
  READ --> VALIDATE[Validate and update in memory]
  VALIDATE --> TEMP[Write process-specific temporary file]
  TEMP --> REPLACE[Atomic os.replace]
  REPLACE --> JSON[(Updated JSON store)]
  EVENT[Usage or admin event] --> APPEND[Append one JSON line]
  APPEND --> LOGS[(usage.jsonl or audit_log.jsonl)]
  JSON --> METRICS[Admin metrics aggregation]
  LOGS --> METRICS
Deployment and security note. Local files are suitable for this single-instance application, but container filesystems may be ephemeral and multiple app instances can contend for shared files. For production scale, place writable data on durable shared storage or migrate it to a transactional database. Treat sap_config.json and admin_config.json as secrets and do not expose them as public static assets.
